doesn't have to guess which doc page covers which part of `index.html` — go straight to the
row that matches the section you're checking. `WebFetch` on this domain is blocked by network
egress in this environment on every attempt so far; don't spend more than one try confirming
that before falling back to `WebSearch` (which reaches cached snippets of the same pages) or
asking the user to paste the page content directly.

## Facts confirmed and decisions made in the 2026-10 audits (WebSearch snippets of the pages named, plus the user's own answers)

- **AI-service** (`castimaging/ai-service`) is a container *inside imaging-viewer* (with ETL, imaging-apis, Neo4j) — gate it on `hasViewer(a)` (docker S1/S2 install pages).
- **PostgreSQL**: 14.x–18.x (64-bit) supported, 18.x recommended for self-provisioned instances; Docker/Podman embedded mode uses a `postgres:15` container; CAST ships no PostgreSQL for Windows (`install/requirements/db/`).
- **CAST Extend Local Server**: Windows service `CAST_ExtendProxy` (Docker image `castimaging/extend-proxy`); can run fully offline with extensions uploaded manually (`doc.castsoftware.com/install/extend-local/`).
- **MCP Server** can be co-located with other CAST Imaging components or put on a dedicated machine (`mcp-server/docker/`).
- **JDK 17–21 64-bit with JAVA_HOME** is mandatory on Windows servers (password encryption), optional on Linux (`install/requirements/precheck/`).
- **Reverse proxy upstream is Gateway :8090** (Nginx `proxy_pass` to 8090 in `install/https-ssl/docker`) — never advise disabling 8090.
- **Source code delivery (user decision, 2026-10-02)**: CAST Imaging v3 takes source as a ZIP upload or from a source folder location every analysis-node can read (`imaging/onboard/register-deliver-source-code/`, `administer/global-configuration/source-folder-location/`). The Git/SVN option is requalified as clones made by the customer's own tooling onto that folder (443 from *their* host, conditional) — CAST doesn't pull from repositories.
- **Delivery/analyst workstation has no JDK requirement** (user decision, 2026-10-02) — JDK is a Windows-server requirement only.
- **PostgreSQL sizing (user decision, 2026-10-02)**: standard/enterprise PostgreSQL disk is exactly 2x/4x the 3072 GB anchor (6144/12288 GB); a co-located PostgreSQL adds its postgresDedicated figures to the row hosting it.
- **Print, export and wording (user decisions, 2026-10-02)**: "Answer the questions on the left…", "Generated live from the answers on the left" and "Regenerated live in your browser" are hidden in print and removed from the HTML export. The Control Panel port notation stays **"8098–2381"** (user-confirmed; audits read the doc as two separate ports 8098 and 2381 — don't change it without asking). A multi-machine **analysis-node → core return-path row** and a **servers → corporate proxy row** (proxy egress) were added at the user's request; both are labelled as inferences/per-customer values.
- **Reverse proxy default (user decision)**: Kubernetes preselects "Kubernetes Ingress controller"; other platforms an external reverse proxy; the user's own pick is never overwritten.
- **Kubernetes storage**: CAST defaults to per-node Azure Disks and moves to Azure Files (shared access) when running **multiple analysis-node pods** (`install/requirements/disk/storage-locations/cloud/`) — so RWX shared storage is only required with several analysis-node pods; this was verified only for AKS (EKS/GKE defaults not checked).
- **CAST's own scenarios are S1 All, S2 Viewer only (no dashboards), S3 Viewer + Analysis, S4 Dashboards only, S5 Dashboards + Analysis** — the tool's scenario list differs, and the user decided (2026-10-02) **not** to align it on S1–S5 — don't re-flag.

## Researched 2026-10-06 (WebSearch summaries only — doc.castsoftware.com stays blocked)

- **Database links — CONFIRMED by CAST (user pasted CAST's answer, 2026-10-09)**: directly connected to PostgreSQL = Control Panel (`castimaging/admin-center`), SSO Service, Auth Service, Console, Dashboards (`castimaging/dashboards-v3`), analysis-node, and imaging-viewer (component level; the container(s) aren't itemised); not connected = Gateway, Extend Local Server (`castimaging/extend-proxy`), Imaging MCP, Gatekeeper MCP. Imaging MCP's semantic and text2cypher tools connect to Neo4j. Hosts must be allowed in `pg_hba.conf` (`install/db/post-install/#configure-network-access-via-pg_hbaconf`); CAST's certificate-based connections page (`install/db/encrypted/components/`) lists analysis-node, imaging-services, imaging-viewer and dashboards. The earlier search-snippet guesses (Console/Control Panel/Dashboards "inferred") are superseded.
- **Extend Local Server feed**: role = intermediary to CAST's public Extend; online = direct connection to `https://extend.castsoftware.com`, downloads any extension requested by CAST Imaging (pull on demand, no schedule documented); offline = no external connection, manually populated, a missing extension fails the analysis at the extension install/update step; manual upload = `.extarchive` built with ExtendCli, `POST /api/synchronization/bundle/upload` on port 8085 with the API key as header (older Extend Offline docs); data in `DATA_FOLDER`, HTTP by default. **No reverse-proxy path, Gateway route or Ingress rule is documented for it** — don't invent a URI.
- **Air-gapped images — CONFIRMED (user pasted CAST's table, 2026-10-06)**: banner "Depending on your chosen deployment scenario, it may not be necessary to download all images". Columns Component / Image / Pull & export / Load. Rows: Gateway `castimaging/gateway`, Control Panel `castimaging/admin-center`, SSO Service `castimaging/sso-service`, Auth Service `castimaging/auth-service`, Console `castimaging/console` (all imaging-services); Dashboards `castimaging/dashboards-v3`; Analysis node `castimaging/analysis-node`; ETL Service `etl-service`, AI Service `ai-service`, APIs Service `imaging-apis`, Viewer Server `viewer`, Neo4j `neo4j` (imaging-viewer); PostgreSQL `postgres:15` (required for 3.0.x–3.5.x-funcrel; from 3.6.0-funcrel only when `DB_MODE=embedded`; tar `postgres15.tar`); curl `curlimages/curl:<ver>` (≥ 3.6.0-funcrel: curl 8.7.1 for 3.6.0, 8.19.0 for 3.6.1+); psql `alpine/psql:latest` (≥ 3.6.0-funcrel with `DB_MODE=external`); CAST Extend Local Server `castimaging/extend-proxy` (no tag). Commands: `docker pull <image>:<ver>` · `docker save <image>:<ver> -o <name>.tar` · `docker load -i <name>.tar`. Earlier guesses were wrong in two places (Dashboards is `dashboards-v3`; Control Panel is `admin-center`). MCP images (user-supplied Docker Hub pages, 2026-10-06): `castimaging/imaging-mcp-server`, `castimaging/gatekeeper-mcp-server`. The tool lists images only (no commands/tar names — user decision) and for Docker, Podman and Kubernetes alike. Still unknown: whether Podman/Kubernetes have their own air-gapped section.

## Open questions (searched, unconfirmed — left unchanged in `index.html` on purpose)

Don't "fix" these from a search snippet alone; raise them with the user or find a primary source.

- **Analysis-node port on Windows**: CAST's Windows install pages (`install/global/windows/s1-all/…`, S3, S5) appear to put the analysis-node service on **8099**, while the tool (and the Docker/Podman reference) says 8089 everywhere. Medium-high confidence, unapplied.
- **SSO Service**: one snippet lists **9002** in addition to 8096. Not added.
- **Other imaging-viewer ports** (8084 login, 8286 GraphRAG, 9000, 9980, 7473): one secondhand snippet, not added.
- **Analysis-node → core return-path ports**: the multi-machine pages say to open the hardware-page ports on each machine; the exact set isn't itemised (hence the inference label on that row).
- **CAST Highlight FQDNs** (`cloud.casthighlight.com`, `auth.casthighlight.com`, `casthighlight-binaries.s3.amazonaws.com`) are not confirmed; the only CAST-documented hosts found were `rpa.casthighlight.com` and `sam.casthighlight.com`.
- **IIS + ARR** as a reverse proxy isn't documented by CAST (its Windows reverse-proxy page recommends NGINX); kept as an option, with a platform-mismatch warning off Windows.
- **Extend Local Server `:8085` protocol** (HTTP vs HTTPS) isn't stated; rows say "HTTP/HTTPS".
- **Browser minimum versions**: only an old export-v2 page lists them; the tool says "Chrome / Edge / Firefox". Report Generator minimums (Imaging 3.4.0-funcrel / Report Generator 1.29.0-funcrel) above are not stated in the tool's text.
- **Where the Extend Local Server sits in an air-gapped network** (it needs outbound 443 in online mode — a DMZ placement may be wanted) and **whether the air-gapped API key is configured on the Local Server** — not covered.

## Using this map

1. Find the row matching the section you're auditing.
2. Try fetching the listed page(s) once each.
3. If blocked, search for the same page's content, or ask the user to paste it.
4. Compare what you find against the specific claim in `index.html` — don't treat "the topic is
   generally covered by this doc" as verification of a specific number, port, or version; find
   the actual sentence that supports (or contradicts) the claim.
5. If a section touches something outside CAST's `imaging` docs entirely (e.g. Docker Hub's own
   pull-path hostnames, generic Kubernetes networking, Neo4j's default Bolt port), say so — it's
   fine for a claim's source to be "Docker's own documentation" or "generic technical fact," but
   don't imply it came from `doc.castsoftware.com` when it didn't.
