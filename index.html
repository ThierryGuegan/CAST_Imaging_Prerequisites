A scenario defines which components are installed; topology (below) defines how they're spread across machines. imaging-services is always required. Source: CAST's "choose your deployment" step at doc.castsoftware.com/imaging/install/global/docker.

Each analysis-node registers itself against the same imaging-services instance and can run on its own machine — this is CAST Imaging's horizontal scaling mechanism for analysis workload.

3 · Database

CAST Imaging supports PostgreSQL only as its RDBMS — no other engine is supported. Analysis and persistence data is stored here.

Neo4j is bundled with imaging-viewer (not user-selectable) — an ETL step loads analysis results from PostgreSQL into Neo4j for graph browsing in the Viewer. Only relevant when your scenario (Section 1) includes the Viewer.

4 · Network egress
5 · Reverse proxy

A reverse proxy (or equivalent load balancer/Ingress) in front of Gateway is a mandatory prerequisite for installation, independent of whether HTTPS is enabled — CAST Imaging is not intended to be run with Gateway directly internet-facing. "Not decided yet" is a valid answer while planning, but must be resolved before install day.

6 · HTTPS

HTTPS/SSL is not mandatory, but highly recommended — see Section 5 for the mandatory reverse proxy it terminates on. "No HTTPS" is a valid choice for a fully trusted, isolated network segment, but is not recommended beyond that.
