4. Reverse Proxy & HTTPS / TLS
A reverse proxy is a mandatory prerequisite. A reverse proxy (or equivalent load balancer/Ingress) in front of Gateway is required for installation, independent of whether HTTPS is enabled — CAST Imaging is not intended to be run with Gateway directly internet-facing.
HTTPS/SSL itself is not mandatory, but highly recommended — except with SAML SSO (Section 5), where it is mandatory. CAST Imaging can be served over plain HTTP through that reverse proxy; enable HTTPS whenever the deployment is reachable beyond a fully trusted, isolated network segment — which in practice means almost every deployment beyond a fully offline POC. SAML SSO is an exception: browsers and IdPs require an HTTPS redirect/callback URL, so HTTPS is a hard requirement whenever SAML is selected (CAST's HTTPS/SSL page states that an HTTPS connection is a prerequisite for configuring SAML authentication).
Reverse proxy: External reverse proxy.
Certificate source: CA-issued.
You must provide the certificate and private key — CAST Imaging does not issue public TLS certificates.
Once HTTPS is confirmed working, disable the reverse proxy's own plain-HTTP listener (port 80) or keep only an HTTP→HTTPS redirect on it. Gateway's 8090 stays the proxy's internal upstream — keep it reachable only from the reverse proxy, not from users.
On Docker/Podman CAST's HTTPS page has NGINX terminate TLS on 443 (listen 443 ssl, ssl_protocols TLSv1.2 in its example) with a PEM key pair whose private key is unencrypted (openssl req -nodes), proxying to imaging-services on 8090; it states that CAST highly recommends not using self-signed certificates and gives no trust-store guidance (per a summary of the page).
NGINX settings in CAST's reverse-proxy examples (per a summary of its Docker and Windows reverse-proxy pages): a single location block with proxy_pass http://<imaging-services-host>:8090/;, the headers Host, X-Forwarded-Proto, X-Real-IP, X-Forwarded-For, X-Forwarded-Host and X-Forwarded-Port, proxy_buffering off, proxy_cache off, proxy_http_version 1.1 with an empty Connection header, client_max_body_size 100M (it limits ZIP uploads at onboarding — raise it if needed) and, for CAST Imaging ≥ 3.4.0 only, proxy_cookie_flags ~.* secure samesite=None;. CAST runs Keycloak behind it with KC_PROXY: edge / KC_PROXY_HEADERS: xforwarded (Docker) or proxy=edge / proxy-headers=xforwarded (Windows). The pages state no proxy timeouts and no /.well-known route (the MCP security page says CAST Imaging handles /.well-known/oauth-protected-resource/mcp itself).
CAST's documented approach is a dedicated Nginx vHost .conf file with ssl_certificate / ssl_certificate_key directives, ssl_protocols TLSv1.2 or higher, and server cipher preference enabled — not a CAST-specific certificate variable.
Use an unencrypted private key ("BEGIN ENCRYPTED PRIVATE KEY" won't load as-is) — strip the passphrase, or supply it to Nginx via ssl_password_file.
Extend Local Server: CAST documents no reverse-proxy path or Gateway route for it — it is not one of Gateway's path-routed services. Imaging components and administrators reach it directly on host:8085 (its upload feed included), so no URI needs adding to your reverse proxy. If your standards require it behind the proxy anyway, publish it on a dedicated hostname or port rather than a Gateway path, and raise the proxy's request-body limit for bundle uploads (not CAST-documented).
Serving CAST Imaging under a URL path prefix (e.g. https://host/imaging) additionally requires setting APP_CONTEXT and editing cast_imaging_services/docker-compose.override.yml — see CAST's reverse-proxy-with-context-URL reference.
5. User authentication prerequisites
HTTPS must already be set up on CAST Imaging (CAST's SAML page; Section 4) — plain HTTP is not a valid choice with SAML.
Export CAST Imaging's own SAML metadata from Keycloak (aip-realm → Realm settings → General → SAML 2.0 Identity Provider Metadata, saved as metadata.xml) and send it to your identity team, who register CAST Imaging as a Service Provider and return an IdP metadata URL.
Declare the IdP in Keycloak (aip-realm → Identity providers → SAML v2.0): the metadata URL goes in SAML entity descriptor and the settings fill in by themselves.
Attribute mappers firstName, lastName and email (type Attribute Importer; Attribute Name = the ClaimType URI found in the IdP metadata; name format ATTRIBUTE_FORMAT_BASIC).
Groups (optional): the IdP must send them in the assertion and group import is not supported — create each group in Keycloak and add an Advanced Attribute to Group mapper per group (key = the group attribute name, value = a regex, Regex Attribute Values on, sync mode Force); the attribute name is read by decoding the SAMLResponse in the browser's DevTools.
Grant the ADMIN profile to at least one SAML user with the local admin account and test the login; CAST then recommends disabling the existing authentication methods (switch SAML off temporarily to see the local users). Keep a documented break-glass procedure for an IdP outage (this tool's recommendation). If SAML is not offered at login, set the realm's Login theme to keycloak.
Network: browser ⇄ IdP over HTTPS (443) and CAST Imaging fetching the IdP metadata (see Section 3) (reasonable inference from the SAML flow — CAST's page names no port).

Source: CAST's Authentication – SAML page (install/authentication/saml).

6. CAST Extend access & licensing
Deploy a CAST Extend Local Update Server inside your network (the extend-proxy container) — all CAST Imaging components then pull from it internally on :8085. In online mode it is CAST Imaging's only CAST Extend connection to the internet (extend.castsoftware.com, port 443); in offline mode it has no external connection at all and extensions are uploaded to it manually.
Extend Local Server requirements (CAST's Extend Local page): a dedicated machine is recommended but needs no powerful CPU, no Java and only about 100 MB of RAM and 2 GB of free disk; a CAST Extend account is needed even offline; it runs as the cast_extendproxy container of castimaging/extend-proxy with -p 8085:8085, a data volume and public_url set to the URL CAST Imaging uses; the Administration Center URL and the API key (APIKEY in config.proxy.json) are what you enter in CAST Extend Settings; inbound 8085 from the analysis-node and imaging-services, and outbound 443 to CAST Extend from this machine only (online mode; its manifest refresh is about every two hours); HTTP by default, HTTPS on a separate CAST page.
Generate an API key from the CAST Extend website and configure it in CAST Imaging / CAST Extend client to authenticate extension downloads.
Obtain a valid CAST Imaging license key from your CAST account team; confirm it covers the modules you selected (MCP/AI: no; Highlight integration: no).
