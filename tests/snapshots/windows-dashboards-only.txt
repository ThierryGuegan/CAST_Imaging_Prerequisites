4. Reverse Proxy & HTTPS / TLS
A reverse proxy is a mandatory prerequisite. A reverse proxy (or equivalent load balancer/Ingress) in front of Gateway is required for installation, independent of whether HTTPS is enabled — CAST Imaging is not intended to be run with Gateway directly internet-facing.
HTTPS/SSL itself is not mandatory, but highly recommended. CAST Imaging can be served over plain HTTP through that reverse proxy; enable HTTPS whenever the deployment is reachable beyond a fully trusted, isolated network segment — which in practice means almost every deployment beyond a fully offline POC.
Reverse proxy: External reverse proxy.
Certificate source: No HTTPS (plain HTTP) — traffic between browser/client and the reverse proxy is unencrypted; reconsider once the deployment is reachable beyond a fully trusted, isolated network segment.
NGINX settings in CAST's reverse-proxy examples (per a summary of its Docker and Windows reverse-proxy pages): a single location block with proxy_pass http://<imaging-services-host>:8090/;, the headers Host, X-Forwarded-Proto, X-Real-IP, X-Forwarded-For, X-Forwarded-Host and X-Forwarded-Port, proxy_buffering off, proxy_cache off, proxy_http_version 1.1 with an empty Connection header, client_max_body_size 100M (it limits ZIP uploads at onboarding — raise it if needed) and, for CAST Imaging ≥ 3.4.0 only, proxy_cookie_flags ~.* secure samesite=None;. CAST runs Keycloak behind it with KC_PROXY: edge / KC_PROXY_HEADERS: xforwarded (Docker) or proxy=edge / proxy-headers=xforwarded (Windows). The pages state no proxy timeouts and no /.well-known route (the MCP security page says CAST Imaging handles /.well-known/oauth-protected-resource/mcp itself).

No external identity provider required.

Generate an API key from the CAST Extend website and configure it in CAST Imaging / CAST Extend client to authenticate extension downloads.
Obtain a valid CAST Imaging license key from your CAST account team; confirm it covers the modules you selected (MCP/AI: no; Highlight integration: no).

Single machine (imaging-services + dashboards)
curl installed — required for the installer's own service health checks (CAST requirements precheck)
Installing user confirmed to have Full Control permissions (directly or via group membership) on the root install folder
Installer package com.castsoftware.imaging.console downloaded from CAST Extend and unzipped to a path without (, ) or !; installation run from an administrator command prompt with Quick Edit disabled (a mouse click pauses the script); install logs in %PROGRAMDATA%\CAST\CAST\.install; for domain mapping (3.5.0 or later, optional) the system variable IMAGING_DOMAIN_SYNCHRO_ENABLED=true set before installing (per CAST's Windows S1 single-machine page)
Windows services verified after installation — 6 services expected for Dashboards only, read-only on one machine, all set to Automatic (they run as LocalSystem unless *_START_AS_USER is set) (per CAST's Windows scenario pages)
After a reboot some services can fail because imaging-services and the analysis-node depend on each other — %PROGRAMFILES%\CAST\Imaging\CAST-Imaging-sync-all-services-on-startup.bat (for machines installed with all or imaging-services) checks the Authentication, Console, Control Panel, Gateway, SSO, Analysis Node and Dashboards services and starts any that are down; run it as administrator (true as its argument when HTTPS is enabled) or schedule it with Task Scheduler — trigger "At system startup", "Run whether user is logged on or not", highest privileges, optionally a delay and a repeat (per CAST's Windows startup-checker page; it does not say which command or flag the scheduled task runs)
Windows Defender Firewall enabled on every profile with the default inbound action Block (a Block rule always wins — no Group Policy block may cover 8090); only 8090 open to users, every other CAST port (including 8098, which is how analysis nodes, dashboards, viewer and MCP machines register) open only from this machine or the other CAST machines — CAST's sample scripts Run-ImagingPortFirewall.bat / Set-ImagingPortFirewall.ps1 (dryrun first, rule group "CAST Imaging Ports") need every other machine's IP or hostname, resolvable, listed on the imaging-services machine; then verified with Test-NetConnection <host> -Port <port> (8090 connects, the rest time out) (per CAST's network-access page; it still lists 8090 as the Gateway port and does not say what changes when HTTPS moves the Gateway to 443)
Dashboards standalone mode enabled — dashboard-standalone-enabled: true under application: in %PROGRAMFILES%\CAST\Imaging\CAST-Imaging-Control-Panel\application-default.yml, then the CAST Imaging Control Panel service restarted (create the file if it does not exist) (per CAST's Windows Dashboards-only page; the other platforms' pages were not read for this)
Installer prechecks (3.6.6 or later) expected to pass — blocking: a 64-bit JDK with JAVA_HOME (Windows Server Core is not supported), curl, resolvable hostnames and mandatory variables, free service ports, memory and disk minimums, an empty installation folder, reachable Extend and Control Panel, database role privileges; warnings: non-UTF8 encoding, tablespace privilege, Docker Hub / Maven reachability; --skip-precheck exists from 3.6.9 but only hides problems until mid-install (verbatim for the first groups, a summary for the others — CAST's prechecks page)
Installer variables decided — IMAGING_SERVICES_HOSTNAME (public FQDN), every HOSTNAME_* either all localhost or all FQDN; CSS_INFOS as host:2284 and CSS_USER / password (the installer proposes operator / CastAIP; other credentials go in CSS_ENCRYPTED_PASSWORD, encrypted with imaging-encryption-tool.bat); DATA_DIR not on a network drive (even mapped); INSTALL_DIR without spaces outside C:\Program Files; SECURED_CONNECTION false for the first install and true when updating after HTTPS or adding a node; the Keycloak kcadmin password stays admin after a fresh install — change it right away (per CAST's Windows installation variables page)
Where the analysis results come from decided — Dashboards only, read-only performs no analysis on this machine: they come from a separate CAST Imaging installation with analysis nodes (S1 or S5 on CAST's pages); CAST Imaging Core is not needed here, and the pages describe no transfer mechanism (per CAST's Windows S2 / S4 pages)
64-bit JDK ≥ 17 LTS and ≤ 25 (CAST Imaging 3.6.7 or later; ≤ 21 before) installed with %JAVA_HOME% set (mandatory on Windows)
Server(s) provisioned meeting the sizing in Section 1 (Windows Server, Dashboards only, read-only, Single machine)
PostgreSQL provisioned as: Dedicated server
PostgreSQL login role is SUPERUSER (or holds CREATEDB and CREATEROLE, with CREATE on the pg_default tablespace) and the database is UTF8 — a non-UTF8 encoding can corrupt analysis data; CAST recommends an operator SUPERUSER with the postgres role granted, pg_hba.conf restricted from its permissive default, listen_addresses set to a specific IP/CIDR, the port set to 2284 instead of 5432, locale C, and postgresql.conf set for an 8 GB profile (max_connections 300, shared_buffers 2GB, effective_cache_size 6GB, work_mem 64MB, maintenance_work_mem 512MB, max_locks_per_transaction 4096, client_encoding 'UTF8', the lc_* settings 'C'; PGTune with max_connections 300 above 8 GB), then the service restarted (per CAST's database requirements and post-install pages)

Values that an update cannot change, decided now: the TCP port of every service and every *HOSTNAME_* variable (and PUBLIC_URL became IMAGING_SERVICES_HOSTNAME / ANALYSIS_NODE_HOSTNAME in 3.6.7); a distributed installation is updated component by component but all on the same release; the CSS_PASSWORD and CSS_ENCRYPTED_PASSWORD must both carry a changed database password, and an update to 3.6.9 needs the PostgreSQL hosting the keycloak schema at 15 or later; keep the Keycloak service-account password variable (KEYCLOAK_SERVICE_ACCOUNT_PASSWORD) if you ever change it in the Keycloak UI — blank, an update resets it to admin (per CAST's Docker and Windows update pages)
Keycloak accounts planned — the UI administrator kcadmin (3.6.0 or later; its name is set at a fresh install with KEYCLOAK_LOGIN_ADMIN_USER) has the temporary password admin, to be changed at first login; the internal service account admin must not be changed in the Keycloak UI alone (login then fails with a Whitelabel error) — its initial password is random from 3.6.6 on Docker/Podman and Kubernetes but admin on Windows; the CAST local user admin / admin must change its password at first login (3.6.5 or later); avoid passwords that are fully quoted, contain a space followed by #, or contain a backslash or slash (per CAST's accounts and passwords page)
