4. Reverse Proxy & HTTPS / TLS
A reverse proxy is a mandatory prerequisite. A reverse proxy (or equivalent load balancer/Ingress) in front of Gateway is required for installation, independent of whether HTTPS is enabled — CAST Imaging is not intended to be run with Gateway directly internet-facing.
HTTPS/SSL itself is not mandatory, but highly recommended. CAST Imaging can be served over plain HTTP through that reverse proxy; enable HTTPS whenever the deployment is reachable beyond a fully trusted, isolated network segment — which in practice means almost every deployment beyond a fully offline POC.
Reverse proxy: External reverse proxy.
Certificate source: CA-issued.
You must provide the certificate and private key — CAST Imaging does not issue public TLS certificates.
CAST's Windows HTTPS procedure (below) terminates TLS at the Gateway itself (server.port: 443), not at a reverse proxy. CAST's Windows reverse-proxy example is HTTP-facing (listen 80, proxy_pass …:8090/) and says nothing about keeping Gateway TLS behind it — if you keep a reverse proxy in front, confirm with CAST which port and protocol it must use towards the Gateway; the 8090 rows of this document are the default HTTP port.
HTTPS on Windows — CAST's procedure (local administrator; commands differ by release — the variants for versions before 3.6.2, 3.6.4 and 3.6.9 are noted; read verbatim from CAST's Windows HTTPS page):
Key pair (OpenSSL isn't shipped — use %PROGRAMFILES%\Git\usr\bin if Git is installed): openssl req -new -newkey rsa:2048 -nodes -keyout private_key.key -out csr.csr; send csr.csr to your CA for public_key.crt. Common Name and a SAN entry must be the public FQDN. CAST highly recommends CA-signed certificates.
SSO Service: from 3.6.9 it needs no certificate — in %PROGRAMFILES%\CAST\Imaging\CAST-Imaging-SSO\conf\keycloak.conf set hostname=https://<FQDN>/auth and add proxy-headers=xforwarded; in 3.6.8 and earlier copy the PEM pair into that conf folder, change http-port=8096 to https-port=8096 and set https-certificate-file / https-certificate-key-file.
Gateway keystore: openssl pkcs12 -export -in public_key.crt -inkey private_key.key -name gateway -out gateway.p12, then keytool -importkeystore -srckeystore gateway.p12 -destkeystore gateway.jks -srcstoretype PKCS12; check the keystore type with keytool -list -v -keystore gateway.jks -storepass <password>; copy gateway.jks to %PROGRAMFILES%\CAST\Imaging\CAST-Imaging-gateway\. Self-signed only: keytool -export -alias gateway -file gateway.crt -keystore gateway.jks, then keytool -importcert -trustcacerts -file gateway.crt -alias gateway -keystore "%JAVA_HOME%\lib\security\cacerts" (default password changeit) — otherwise services fail with "PKIX path building failed".
Gateway configuration (CAST-Imaging-gateway\application-default.yml, application.yml before 3.6.2): server.port: 443, server.ssl.enabled: true, an SSL bundle on gateway.jks (location, type, password), server-name-bundles mapping the FQDN (3.6.4+; otherwise ERR_CONNECTION_CLOSED through the FQDN), forward-headers-strategy: framework and tomcat.remoteip.remote-ip-header: x-forwarded-host.
Authentication service (CAST-Imaging-auth-service\application-default.yml): from 3.6.9 server.port: 8092 and service.gatewayPort: 443 with no gatewayUrl/nginx entries, then set the machine variable PUBLIC_URL to https://<FQDN> (no trailing slash; elevated PowerShell [Environment]::SetEnvironmentVariable('PUBLIC_URL', 'https://<FQDN>', 'Machine')) and restart the machine; in 3.6.8 and earlier service.auth: https://localhost:8096, gatewayPort: 443, and gatewayUrl and nginx set to https://<FQDN>.
Database: in the control_panel schema (admin_center in 3.2 and earlier), table properties, change keycloak.uri to HTTPS and remove the port.
Restart order: SSO, Control Panel, Gateway, then the Authentication service (only once the Gateway has started), Console, Analysis Node, Dashboards, and the Viewer services (Neo4j first). Test https://<FQDN> in a browser.
Analysis nodes added later: set SECURED_CONNECTION to true in config-analysis-node.conf.
Typical failures per CAST: "PKIX path building failed" (certificate missing from the Java trust store), "Keystore was tampered with, or password was incorrect", "Invalid keystore format", a SAN that doesn't match the FQDN, and a /login?error loop in 3.6.9+ (PUBLIC_URL unset or gatewayUrl still set).
NGINX settings in CAST's reverse-proxy examples (per a summary of its Docker and Windows reverse-proxy pages): a single location block with proxy_pass http://<imaging-services-host>:8090/;, the headers Host, X-Forwarded-Proto, X-Real-IP, X-Forwarded-For, X-Forwarded-Host and X-Forwarded-Port, proxy_buffering off, proxy_cache off, proxy_http_version 1.1 with an empty Connection header, client_max_body_size 100M (it limits ZIP uploads at onboarding — raise it if needed) and, for CAST Imaging ≥ 3.4.0 only, proxy_cookie_flags ~.* secure samesite=None;. CAST runs Keycloak behind it with KC_PROXY: edge / KC_PROXY_HEADERS: xforwarded (Docker) or proxy=edge / proxy-headers=xforwarded (Windows). The pages state no proxy timeouts and no /.well-known route (the MCP security page says CAST Imaging handles /.well-known/oauth-protected-resource/mcp itself).
Only if you terminate TLS on NGINX instead of at the Gateway (CAST's Windows procedure above does it at the Gateway): CAST's documented approach is a dedicated Nginx vHost .conf file with ssl_certificate / ssl_certificate_key directives, ssl_protocols TLSv1.2 or higher, and server cipher preference enabled — not a CAST-specific certificate variable.
On NGINX: Use an unencrypted private key ("BEGIN ENCRYPTED PRIVATE KEY" won't load as-is) — strip the passphrase, or supply it to Nginx via ssl_password_file.
5. User authentication prerequisites
A directory reachable by Keycloak (user federation in aip-realm; CAST's page gives the connection URL as ldap://<host> and names no port, LDAPS or certificate) and a dedicated bind (service) account — bind type simple, Bind DN and credentials — checked with Test connection and Test authentication.
Users DN (the OU that holds the users); on Active Directory: vendor Active Directory, username attribute sAMAccountName, UUID attribute objectGUID; edit mode UNSYNCED when importing users (Import users on — users are imported at their first login — and Periodic Full Sync on), Sync Registrations off.
Size limit: CAST tested up to 5,000 LDAP users synchronised into Keycloak; above that the synchronisation may become unreliable.
Group mapping (group-ldap-mapper): LDAP Groups DN, group name attribute cn, membership attribute member (or memberUid), mode IMPORT recommended, and on Active Directory the retrieve strategy LOAD_GROUPS_BY_MEMBER_ATTRIBUTE_RECURSIVELY (recommended by CAST). Users who logged in before the mapper existed must be deleted so their groups are read again.
Passwords are verified against the directory at every login; a user deleted from it can no longer log in.
Grant the ADMIN profile to at least one LDAP user or group with the local admin account, then disable or delete the local users and groups (switch LDAP off temporarily to see them).
If using LDAPS (636), the directory's CA certificate must be trusted by CAST Imaging's SSO Service (on the machine running imaging-services) (general requirement — CAST's LDAP page does not mention LDAPS).

Source: CAST's Authentication – LDAP page (install/authentication/ldap).

6. CAST Extend access & licensing

7. MCP Servers (AI features) — enabled
Deploy the CAST Imaging MCP Server 3.1: one Windows service (cast-imaging-mcp-server, registered in the Control Panel as MCPSERVER) runs the MCP Aggregator Gateway on :8285 with the Structural (8282), Semantic search (8287) and Text2Cypher (8289) MCP servers behind it on its loopback; it needs CAST Imaging 3.6.9 or later and is reached through Gateway on the /mcp path — clients never connect to :8285 directly. Windows: CAST documents a native install — mcp-server-installer.bat --install configuration.conf from an elevated CMD, deployed as the Windows service CAST Imaging MCP Server (cast-imaging-mcp-server); no Java needed, Neo4j reachable over Bolt, at least 2 GB free disk; Windows may not restart the service after a reboot (CAST suggests a startup task running mcpserver_syncronization.bat). Restrict :8285 to the imaging-services and imaging-viewer machines. Docker or WSL for the MCP servers isn't documented. Per a summary of CAST's Windows page (not read verbatim).
Database access: the MCP servers do not connect to PostgreSQL (not stated on CAST's MCP pages). The Semantic search and Text2Cypher servers connect to Neo4j (Bolt 7697, part of your Viewer scenario).
Gatekeeper MCP (Gatekeeper-MCP-Server, TCP 8283, path /mcp/gatekeeper) is a standalone service installed alongside the MCP Server: it connects AI clients to the CAST Dashboard REST API (/dashboards/rest on imaging-services; API-key sign-in needs CAST Imaging 3.6.6 or later, the component itself 3.6.4 or later). Windows: package com.castsoftware.gatekeeper.mcpserver, mcp-server-installer.bat --install configuration.conf from an elevated CMD, service Gatekeeper-MCP-Server; configuration.conf needs HOST_CONTROL_PANEL and SERVICE_HOST (neither localhost) and MCP_SERVER_PORT=8283; no Java, at least 2 GB disk; open inbound TCP 8283, then check /mcp/healthcheck on :8283 (CAST's Gatekeeper Windows guide). Its telemetry push to CAST is on by default (TELEMETRY_PUSH_ENABLED, every 120 minutes; the host isn't stated) — set it to false on networks without outbound access.
Client authentication (CAST's MCP security page): an API key sent in the x-api-key header (still supported), or an OAuth browser sign-in for Claude Code and VS Code — one or the other per client. The identity provider is CAST Imaging's own Keycloak (realm aip-realm, kcadmin), not an external one: the page mentions no external OAuth2/OIDC provider. OAuth needs CAST Imaging 3.6.6 or later, MCP Server 3.0.4 or later and Gatekeeper 3.0.1 or later. In Keycloak (Realm settings → Client policies) create, per AI client, a profile with the client-id-metadata-document executor and a policy, and link the profile to the policy (CAST calls a missing link the most common mistake): Claude Code — cimd-profile-claude / cimd-policy-claude, trusted domains claude.ai, localhost, 127.0.0.1; VS Code — cimd-profile-vscode / cimd-policy-vscode, trusted domains vscode.dev, code.visualstudio.com, 127.0.0.1. Clients reach only the Gateway (/mcp, /mcp/gatekeeper, and /.well-known/oauth-protected-resource/mcp, which CAST Imaging redirects to Keycloak's discovery endpoint) — never expose the MCP Server or Keycloak directly. HTTPS is highly recommended; plain HTTP is acceptable only on a trusted local or CI host not reachable from the internet. Check: an unauthenticated POST to /mcp must answer with a WWW-Authenticate: Bearer resource_metadata=… header.
LLM provider selected: Anthropic API — allowlist exact FQDN api.anthropic.com on the MCP client hosts, not the CAST Imaging servers (no wildcards).
Licensing and settings (CAST's MCP 3.1 pages): from CAST Imaging 3.6.9 the Semantic search MCP needs a license key that includes GraphRAG (otherwise it reports "Not licensed"); IMAGING_CODE is false by default, so source code is not returned to the AI client; a private or self-signed CA needs SSL_CA_BUNDLE (Base-64 PEM, root and intermediate combined); with domain mapping clients still send x-user-tenant; CAST says the MCP Server and Keycloak must never be exposed directly and HTTPS on the CAST Imaging gateway is highly recommended.
Update and logs (per a summary of CAST's MCP update page): run mcp-server-installer.bat --update from an elevated prompt after setting SERVICE_HOST and NEO4J_URL in configuration.conf; logs in %CONFIG_DIR%\logs\mcp_server.log. The MCP tool profile is reset to the default intents on update.
Sizing: CAST's MCP pages give only at least 2 GB of free disk (CPU and RAM: the general hardware requirements) and don't say whether the MCP servers can share a machine with other CAST Imaging components; the MCP servers have their own installers. The ~2 vCPU / 4 GB RAM / 20 GB disk added to the core row in Section 1 (Imaging MCP + Gatekeeper MCP combined) is this tool's estimate, not a CAST figure — split it out yourself if you need per-service limits.
