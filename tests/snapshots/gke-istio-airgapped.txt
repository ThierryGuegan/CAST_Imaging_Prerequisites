4. Reverse Proxy & HTTPS / TLS
A reverse proxy is a mandatory prerequisite. A reverse proxy (or equivalent load balancer/Ingress) in front of Gateway is required for installation, independent of whether HTTPS is enabled — CAST Imaging is not intended to be run with Gateway directly internet-facing.
HTTPS/SSL itself is not mandatory, but highly recommended. CAST Imaging can be served over plain HTTP through that reverse proxy; enable HTTPS whenever the deployment is reachable beyond a fully trusted, isolated network segment — which in practice means almost every deployment beyond a fully offline POC.
Kubernetes networking (CAST's chart 3.6.9): exactly one of CreateLoadBalancer (default; exposes console-gateway-service as a cloud LoadBalancer), CreateIngress, UseIstioGateway or UseGatewayAPI (a GatewayClass controller such as NGINX Gateway Fabric). The Ingress template is nginx-specific (ingressClassName: nginx, nginx.ingress.kubernetes.io/* annotations) — install an ingress-nginx controller first; TLS comes from the Kubernetes secret tls-secret-cast (and tls-secret-cast-extend for the Extend proxy host) that you create in the CAST namespace (istio-system with Istio). The chart sets X-Forwarded-Host/-Proto/-Port from FrontEndHost, which matters when a reverse proxy or DMZ sits in front of the Ingress. Timeouts: NetworkTimeoutSeconds 300 s (Extend proxy 3600 s) — keep any outer proxy at least that high. Since 3.6.9 the gateway only forwards X-Forwarded-* headers when GATEWAYSERVICE.SPRING_CLOUD_GATEWAY_SERVER_WEBFLUX_TRUSTEDPROXIES is set (default ".*", a regex on the calling IP — restrict it to your ingress/Istio pod network if you wish); without it the OAuth2 login callback is built as http://, so any reverse proxy, load balancer or DMZ in front of the networking option must forward the original X-Forwarded-Proto/X-Forwarded-Host. With CreateIngress, CertManager.enable (off by default; issuer default vault-issuer, issuerKind, privateKeySize 4096) lets an already-installed cert-manager issue and renew tls-secret-cast.
Istio Ingress Gateway (CAST's GKE page): set UseIstioGateway: true (the page's Istio step writes CreateIstioGateway in one place and UseIstioGateway elsewhere and in its values reference — check values.yaml); Istio is installed separately (istioctl install --set profile=default -y) unless the cluster already runs it — ask your administrator; to attach to an existing gateway set ExistingIstioGatewayName: "namespace/gateway". The TLS secrets tls-secret-cast (and tls-secret-cast-extend) are created in istio-system, not in the CAST namespace. DNS points at the istio-ingressgateway service's external IP.
Reverse proxy: Istio Ingress Gateway.
Certificate source: CA-issued.
You must provide the certificate and private key — CAST Imaging does not issue public TLS certificates.
Once HTTPS is confirmed working, disable the reverse proxy's own plain-HTTP listener (port 80) or keep only an HTTP→HTTPS redirect on it. Gateway's 8090 stays the proxy's internal upstream — keep it reachable only from the reverse proxy, not from users.
Extend Local Server: in CAST's Helm chart 3.6.9 it is the extendproxy pod (ExtendProxy.enable: true, port 8085; in-cluster components reach it as extendproxy:8085), published through your networking option on ExtendProxy.exthostname: under the /extendproxy path of the shared host when it equals the FrontEndHost host (Ingress / Gateway API / Istio; request body limit 3072m, timeout 3600 s), or on its own hostname with the tls-secret-cast-extend secret; with CreateLoadBalancer it is a LoadBalancer/NodePort Service on ExtendProxy.port. Plan that hostname, its DNS record and certificate with the rest of Section 4.
